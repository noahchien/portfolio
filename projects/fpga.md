## 下單前風控閘道：把業務規則變成可驗證的硬體邏輯

每筆委託送出前，都需要檢查價格、額度、庫存等規則。目標是在硬體內以固定、可預期的延遲完成檢查，同時維持既有系統應有的阻擋能力。

### 從規則與驗證基準開始

風控規則散落在兩代既有系統，彼此存在差異。我先逐條萃取成機器可讀的規則表，釐清**57條差異**，讓開發與測試有共同依據，規則變動也能追查影響。

驗證採雙基準比對：同批委託送入現行風控參考模型與FPGA設計，逐筆比較准駁；上板後再比較實機與模擬結果。提供的測試結果為違規0筆，另以**12種刻意改壞的資料**確認比對流程確實能抓出錯誤。這些是該批測試結果，不代表所有未來情境零錯誤。

### 延遲與實機整合

| 項目 | 結果與範圍 |
| --- | --- |
| FPGA內部風控判斷 | **300 MHz、109個時脈，約0.36 µs**；不是完整交易往返延遲 |
| 系統整合 | **接手交大專案後，五個月內完成整合**，以既有基礎延伸 |
| 測試環境 | 委託在證交所測試環境成交；不等同正式營運上線 |
| 刪單 | FPGA保留原單資料，補齊刪單所需資訊；測試環境下證交所於3 ms內回覆成功，非普遍延遲保證 |
| 時序 | 設計在300 MHz下通過時序，整理實機與模擬差異為上板前檢查清單 |

刪改單電文不帶完整原單資訊，因此在新單送出時，由FPGA保留後續所需的原單資料。連線部分則處理序號與重連規則，避免斷線或重開機後重複送單；狀態無法確認時先停止並人工核對。

**技術：**Alveo U50、HLS C++、10G Ethernet／TCP、FIX 4.4、300 MHz時序收斂。

## 期權平價套利系統：讓模擬通過的設計，在實機上跑對

原系統由大學團隊開發，即時接收期交所行情，在硬體計算買權、賣權與期貨的價差並下單。我負責測試驗證，從計數器、行情解碼與網路環境逐層找出實機問題。

| 問題 | 判斷與修正 | 對照結果 |
| --- | --- | --- |
| 實機送出不應出現的套利委託 | 逐段讀取計數器，定位到硬體合成時被固定成常數的變數，再修正 | **同一晚、同一行情測試，錯誤委託由60筆降至0筆** |
| 商品比對長期為0 | 確認行情格式與解碼器不符，改寫解碼 | 成功比對由0升至241,770次，為提供的該次觀測結果 |
| 連線時好時壞 | 分層排查後定位到主機與FPGA使用相同網路位址 | 停用衝突的主機網卡後，該次連線成功 |
| 行情服務差異 | 釐清每秒8次彙整與逐筆行情的取得方式 | 實測FPGA能穩定接收逐筆行情 |

## 人力與AI協作：判斷、驗證及品質責任仍由我承擔

開發人力從三人縮減至一人後，我調整工作分配，將大部分程式實作交由AI協助，自己負責專案規劃、進度、方向判斷、程式審查、現場確認與驗證方式。依原先預估的開發工期比較，開發進度提前一年以上。

AI曾將現場雙網卡誤認成單網卡；這時需要我確認機器配置、補足正確資訊，再引導修正。這個協作例子與上方套利系統的位址衝突案例分開描述，不假定是同一事件。

## 我解決問題的方式

- **先看證據：**用計數器、檔案雜湊與封包紀錄定位差異，沿管線逐段追查。
- **實機與模擬都要驗：**上板後逐位元組比較結果，不以模擬通過取代實機確認。
- **先整理規格：**規則、電文格式、異常處理先形成可檢查依據。
- **狀態不明先停止：**留下證據、人工核對，再決定如何恢復。
