**繁體中文**　／　[English](fpga.en.md)

## 專案概要

| 項目 | 說明 |
| --- | --- |
| 挑戰 | 領域較冷門、偏邏輯電路，開發人力由三人減為一人 |
| 我的責任 | 專案規劃、開發、進度追蹤、程式審查、驗證方式及品質方向 |
| 協作方式 | 初期自行開發；人力不足後，大部分程式實作由AI協助，仍由我負責判斷與審閱 |
| 開發成果 | 完成開發，較原先預估的開發工期提前一年以上 |
| 目前狀態 | 尚未正式上線，作為後續專案延伸的技術基底 |

## 真正需要解決的問題

人力縮減後，不能只把原有工作全部照搬到一個人身上。我需要取捨實作與規劃的分配方式，同時保留對技術方向和品質的掌握。

我採用AI協作開發，將大部分程式實作交由AI協助，自己負責讀程式、確認方向、決定驗證方法，以及判斷接下來要怎麼調整。

## 一個代表性的判斷過程

AI並不天然知道現場的實際機器配置。一次開發過程中，它把實際的雙網卡環境誤認成單網卡，因而對網路配置產生錯誤理解。

我核對現場環境、補足正確資訊，指出原先假設與事實的差異，再配合AI修正。這類問題需要工程師同時理解專業領域與現場，才能分辨：是程式邏輯有問題，還是它一開始就理解錯了環境。

## 我的驗證原則

先理解系統最終應該達成什麼，再決定如何驗證AI產出。程式的說明是否合理，不能替代實際結果是否符合需求。

我的責任包括規劃驗證方式、審查產出、補足現場資訊，以及依照目標判斷結果。這也是我使用AI時，持續由自己承擔的工程責任。

## 成果的範圍

「提前一年以上」比較的是原先預估的開發工期。專案尚未正式上線，目前作為下一個專案的基底，不宣稱已投入正式營運，也不附加未提供的效能數據。

這個案例呈現的是資源調度、AI協作、現場判斷與品質責任。受工作保密規範限制，不公開公司程式碼、IP、硬體型號或內部架構。
