# FPGA 低延遲交易系統

**繁體中文**　／　[English](fpga.en.md)

交大原訂五年的產學合作案，我在第三年中途接任專案 PM，負責整合、開發與驗證。之後開發人力由三人縮為一人，依原訂工期估算，開發提前一年以上完成。

| 系統 | 我的角色 | 代表成果 |
| --- | --- | --- |
| 下單前風控閘道 | 主導需求分析、架構、開發與驗證 | FPGA 內風控判斷約 0.36 µs；五個月從可行性評估做到證交所測試環境成交、刪單 |
| 期權平價套利系統 | 交大開發初版；後段實機除錯、修正與期交所串接由我主導 | 錯誤委託 60 → 0；行情解碼 0 → 241,770 次；FPGA 直接登入期交所 |

## 下單前風控閘道

每筆委託送出前，都要先檢查價格、額度、庫存等規則。過去由伺服器軟體處理，這個系統把檢查搬進 FPGA，用固定時間完成，而且不能比原本的系統少擋任何一筆該擋的單。

### 規則與驗證

風控規則散在兩代既有系統裡，彼此還有差異。我先逐條整理成機器可讀的規則表，理清 57 條差異。開發和測試都以這份規則表為準，規則有變動時也追得到影響範圍。

驗證用雙基準比對：同一批委託同時給現行系統的參考模型和 FPGA，逐筆比對准駁，違規 0 筆。上板後再比對實機和模擬，並用 12 種故意改壞的資料確認比對真的抓得到錯。

### 延遲與交易所介接

| 項目 | 結果 |
| --- | --- |
| FPGA 內風控判斷 | 109 個時脈（300 MHz），約 0.36 µs；這是 FPGA 內部處理時間，不含網路往返 |
| 交易所 | 在證交所測試環境完成登入、委託成交與刪單 |
| 刪單 | 刪單電文缺少原單資訊。FPGA 在送出新單時保留一份原單資料，刪單時在硬體內補齊，證交所 3 ms 內回覆刪單成功 |
| 連線安全 | 處理連線序號與斷線重連，避免重複送單；狀態無法確認時先停下、人工核對 |
| 時序 | 300 MHz 時序收斂；把模擬看不到、只在實機出現的行為整理成上板前檢查清單 |

系統目前作為後續專案的基礎，還沒有正式上線。

`Alveo U50` · `HLS C++` · `10G Ethernet / TCP` · `FIX 4.4` · `300 MHz`

## 期權平價套利系統

系統即時接收期交所行情，在硬體上計算買權、賣權與期貨之間的價差，出現套利空間就由 FPGA 下單。初版由交大團隊開發，模擬全部通過，接上真實行情後卻問題不斷。後段的實機除錯、修正與期交所串接由我主導。

| 問題 | 怎麼查、怎麼修 | 結果 |
| --- | --- | --- |
| 實機一直送出不該有的套利委託 | 逐段讀計數器，追到一個在硬體合成時被固定成常數的變數 | 同一晚、同一行情的對照測試，錯誤委託由 60 筆降為 0 |
| 商品比對次數一直是 0 | 行情格式和解碼器對不上，改寫解碼器 | 成功比對由 0 升到 241,770 次 |
| 串接期交所 | 接上正式行情線，讓 FPGA 自己直接登入期交所。登入一度連續失敗，原本懷疑硬體故障，查到是主機和 FPGA 用了同一個網路位址 | 關掉主機那張網卡後一次成功，期貨、選擇權兩條連線都完成登入 |
| 行情頻道 | 釐清每秒 8 次的彙整行情和逐筆行情各自怎麼取得 | 實測 FPGA 能穩定收到逐筆行情 |

## 一個人怎麼做完

人力剩我一個之後，實作大量交給 AI 工具，我負責規劃、進度、技術方向、程式審查、現場確認和驗證。工具給的答案不一定對：它曾把現場的雙網卡誤認成單網卡，要靠我確認機器實際配置再導正。所以每個結論我都要求有證據，計數器、封包紀錄、實機和模擬的逐位元組比對，對不上就停下來查。

## 做事的方式

- **先看證據**：用計數器、檔案雜湊和封包紀錄找差異，沿著資料流一段一段查。
- **實機和模擬都要驗**：上板後逐位元組比對，模擬通過不代表實機正確。
- **規格先寫清楚**：規則、電文格式、異常處理先寫成可以檢查的規格。
- **狀態不明就停**：留下證據、人工核對，再決定怎麼恢復。
