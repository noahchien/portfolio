# 長篇小說 × 內容工程

## 想解決的問題

長篇創作累積大量章綱、人物與設定後，容易出現版本不一致、人物知情錯位和改綱未連動的問題；電腦上的原稿也不方便直接用手機審閱。

## 目前的做法

- 使用 Git 保存章節、設定與編輯紀錄，區分正式採用版本、草稿和歷史內容。
- 以 JavaScript 工具檢查章號、章名與來源一致性，產生連續閱讀版。
- 將人物及關係整理成資料，產生可縮放的關係圖。
- 將中篇章綱輸出成每頁最多50章的手機閱讀副本，標示整合稿及候選稿。
- 以作者決策、AI 草擬、主編複核的分工方式處理內容。

## 可核對的完成度

截至本次盤點，主專案正式正文到第35章；第36—37章仍待修。章綱規劃延伸至3500章，手機閱讀副本涵蓋第38—3500章，共3463章；其中1463章來自整合稿，2000章來自待審候選。這些數字代表內容規劃與管理規模，不代表3500章正文已完成。

## 我的角色與協作

我決定故事、角色與創作方向，提出修改要求並審閱結果。AI 協助草擬、工具實作及整理；版本與狀態文件用來支援持續交接。

## 還在改善

將閱讀網站與工作電腦分離，並加入受控存取；GitHub 作為私人備份，Mac 保留為主要 Git 遠端。
